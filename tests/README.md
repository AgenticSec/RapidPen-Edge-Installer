# Edge Installer のテスト

インストーラを実際のコンテナ上で動かし、**利用者の端末から見た振る舞い**を検証する。

対話入力の不具合は、シェルスクリプトを読むだけでは見つからない。実端末（pty）を用意して
実際に打鍵しないと再現しないためで、このテストは `expect` で実端末を作って操作する。

## 実行方法

```bash
./tests/run.sh                        # 全ケース（既定は ubuntu:22.04）
./tests/run.sh --base debian:12       # ベースイメージを指定
./tests/run.sh interactive-normal     # ケースを指定（複数可）
./tests/lint.sh                       # 構文チェックと静的解析
```

必要なもの: `docker` / `expect` / ネットワーク（インストーラが GitHub Release を参照するため）。

## ケース一覧

| ケース | 条件 | 期待する振る舞い |
|---|---|---|
| `interactive-normal` | 通常の端末で対話入力 | 入力が受け付けられ次の手順へ進む |
| `interactive-no-icrnl` | 端末の `icrnl` が無効 | 入力が受け付けられる |
| `interactive-trim` | 末尾に空白を付けて API キーを入力 | 空白が除去されて保存される |
| `input-timeout` | 何も入力しない | 有限時間で終了し、復旧手順を表示する |
| `non-interactive` | 環境変数で API キーと Base URL を渡す | 入力を求めずに進む |
| `no-tty` | 制御端末なし・環境変数なし | 非ゼロ終了し、環境変数による代替手段を案内する |

### `interactive-no-icrnl` について

端末の `icrnl`（CR→NL 変換）が無効だと、**打鍵した文字は端末のエコーで画面に出るのに、
`read` には改行が届かない**。利用者からは「入力できているのに反応がない」ようにしか見えず、
原因にたどり着けない。トヨタ様から報告された事象（チケット #6）がこれで、
その回帰を防ぐためのケース。

### `interactive-trim` について

API キーはコピー＆ペーストで入力されるため、末尾に空白が混入しやすい。
そのまま保存すると認証に失敗する。従来の `read -r` は前後の空白を除去しており、
その挙動を壊していないかを見る。

## XFAIL（既知の失敗）

`run.sh` の `XFAIL_CASES` に載せたケースは、失敗しても全体の結果を赤にせず `XFAIL` として
報告する。まだ直っていない不具合をテストとして先に書けるようにするための仕組み。

- 不具合を直す PR では、`XFAIL_CASES` から該当ケースを外して `PASS` になることを示す
- `XFAIL_CASES` に載っているケースが通った場合は `XPASS` として報告される。
  直ったのにリストに残っている状態なので、リストから外すこと

## 仕組み

インストーラは本番では次の形で実行される。

```bash
curl -fsSL .../install.sh | sudo sh
```

この形では `sudo` の標準入力がパイプになり、そこから呼ばれる `setup.sh` も EOF 済みの
パイプを標準入力として受け取る。対話入力の問題はこの構造と関係するため、テストでも
同じ形を保っている（`tests/bootstrap.sh` が `install.sh` の役割を担い、GitHub から
アーカイブを取得する部分だけを作業ツリーの内容に差し替えている）。

コンテナ内の構成は以下のとおり。

- **`docker`（`docker-stub.sh`）**: イメージ取得は行わない。20GB 近い Operator イメージを
  CI で引くのは現実的でなく、取得の成否はインストーラのロジックとは独立しているため
- **`systemctl`（`systemctl-stub.sh`）**: `start agenticsec-supervisor` だけを失敗させ、
  そこでインストーラを終わらせる。コンテナに systemd が無いことに加えて、
  失敗時クリーンアップ（`cleanup_on_error`）が `/etc/agenticsec` を丸ごと消してしまい、
  生成された `state.json` を検査できなくなるのを避ける狙いがある
- **`setpriv` による降格**: `su` / `runuser` は新しいセッションを作って制御端末を落として
  しまうため使えない。実端末を保ったまま一般ユーザーになるために `setpriv` を使う
- **`Defaults use_pty`**: Ubuntu / Debian の既定に近づけてある。この条件でも対話入力が
  通ることを確認するため

## ケースを追加するには

1. `tests/case.sh` にコンテナ内の条件を足す
2. 対話が要るなら `tests/drive.exp` に、要らないなら `tests/run.sh` に判定を足す
3. `tests/run.sh` の `ALL_CASES` に名前を足す
4. 現行コードで失敗するケースなら `XFAIL_CASES` にも足す
